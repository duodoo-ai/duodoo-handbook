**标题：【出海 ERP】国内客户和国外客户：同一工厂两套销售口径怎么录单？**

> 延伸阅读「出海 ERP」第 4 篇 · 2026-10-21 发布  
> 上篇：[合同评审单](./07-出海ERP-合同评审单从接单到排产.md) · 系列起点：[自产/贸易决策树](./05-出海ERP-没库存时自产自销还是转口贸易.md) · [专栏索引](./README.md)

「客户不就是客户吗？」——在 **单一市场、单一法人** 的工贸厂里，这话勉强成立。在 **海外制造主体** 上，销售往往是 **国内大客户 + 境外关联公司 + 终点国最终用户** 的组合；同一栋楼里的销售部，上午报的是 **本地含税价**，下午报的是 **FOB/DDP 价**。若 ERP 里只有一张客户表、一个价格表、一个出库类型，月底会出现：**收入对了、税错了**；或 **税对了、法人错了**。

这类厂子的业务骨架常是 **销售两种（内/外）、采购两种（内/外）**（见 [出海 ERP 决策树](./05-出海ERP-没库存时自产自销还是转口贸易.md)）。录单不是多填一个字段，而是 **从订单类型起就分叉**。下面是一张 **最小维度表**，适合写进蓝图工作坊，开源 Odoo 与年费套件都按维度配置，不叫「模块名不同」就糊弄过去。

### 录单前先定的 5 个维度（比「客户名称」重要）

| 维度 | 国内客户典型 | 国外/跨境典型 | 系统里建议 |
|------|--------------|---------------|------------|
| **交易主体** | 本法人本地销售 | 本法人出口或跨境销售 | 公司/分支、日记账 |
| **客户角色** | 本地终端或本地集团客户 | 境外关联公司、EPC、终点国用户 | 客户主数据 + 「开票对象」与「收货对象」可不同 |
| **税务意图** | 本地 VAT/发票规则 | 出口免税或目的国规则 | 税映射、发票类型、fiscal position |
| **贸易条款** | 本地交付为主 | FOB/DDP/CIF 等 | 订单模板、价外费用字段 |
| **报表归属** | 本地收入分析 | 出口/区域/产品线 | 分析账户、销售团队、国家维度 |

**一个客户字段糊到底** 的典型后果：集团采购单和海外终端用户共用一个 Partner，直发时 **收货方** 无法区分；或内销价套用在外销 SO 上，财务按出口做了，销售按含税报了。

### 「两个客户」不等于两套乱账

常见三种合法结构（脱敏表述）：

1. **本地大客户**：在本国注册的终端或大型供应链客户 → 内销 SO，**VAT/本地发票** 按当地税政列示（常见要求：仅内销价税分离展示，出口另轨）。  
2. **境外关联公司**：集团内兄弟公司向本工厂采购 → 可能是 **内部销售价** + 后续集团再对终点国销售；系统里要有 **集团客户** 与 **外部客户** 区分，合并报表走抵消规则（一期可先保证 **法人内账清楚**）。  
3. **终点国用户**：货直发第三国，订单上 **客户** 可能是关联公司，**收货地址** 是终端；与 [出库前三问](./06-出海ERP-销售出库前系统必须回答的三个问题.md) 的货权问题直接相关。

录单培训里应有一句：**选客户 = 选合同主体；选地址 = 选物流与收货；两者不要默认永远相同。**

### 一单走读（脱敏）：集团接单、海外工厂生产、直发终点国

下面用 **甲出海集团 + 乙海外工厂 + 丙国终端** 走一遍（无真实公司名）：

| 步骤 | 业务现实 | 系统里建议谁录什么 |
|------|----------|-------------------|
| 1 | 丙国终端向 **甲集团** 签销售合同（DDP 丙国仓） | **甲** 的 CRM/SO（若集团 ERP 在总部） |
| 2 | 甲向 **乙工厂** 下采购（产地乙国、直发丙国） | **甲 PO** ↔ **乙 SO**（关联公司客户=甲） |
| 3 | 乙无库存，走自产 | 乙：**外销或内部销售 SO 类型** + [评审](./07-出海ERP-合同评审单从接单到排产.md) |
| 4 | 物流直发丙国 | 乙发货单：**收货方=丙国地址**；开票对象可能是 **甲** |
| 5 | 收入与税 | 乙按 **出口/跨境规则** 记账；甲在其法人下对丙国销售 |

**一期最低要求**：乙工厂账上能回答——**这张 SO 的客户是谁、货发给谁、算内销还是外销、贸易条款哪一套**。做不到，合并报表再漂亮也是总部 Excel 拼的。

### 集团关联交易：一期做还是二期做？

| 策略 | 一期 | 二期 |
|------|------|------|
| **只上乙工厂法人** | 乙只录 **对甲的 SO**（甲在客户主数据标「集团关联」） | 甲–乙自动对账、intercompany PO/SO 镜像 |
| **甲乙都上** | 定义 **内部客户价目表** + 禁止对外误用 | 合并抵消、转移定价审计 trail |

建议 SOW 写清：**一期以乙法人关账为准**；甲总部系统对接（接口或月结对账表）单列里程碑，别藏在「以后再说」。

### 常见反例（顾问现场高频）

1. **外销 SO 套内销税**：销售图省事选默认税，财务月底改凭证——应在 **外销订单类型** 上绑定 **出口 fiscal position**，创建时不可改税（或改税需财务角色）。  
2. **一个 Partner 兼终端又兼集团**：直发丙国时发货单无法选 **收货地址**，货权与对账全乱——应 **终端建独立地址/子联系人**，或 **发货地址与开票客户分离**。

### 订单入口：一套系统，两种（或多种）订单类型

不必两套 ERP。建议：

- **订单类型 / 单据序列**：内销 SO、外销 SO、内部关联交易 SO（若适用）分开编号规则，默认带出不同的 **价格表、税、付款条款、贸易条款**。  
- **价格表**：内销常含本地费用结构；外销常拆 **海运费、保险、报关** 是否含在价内（回到 [决策树价外费用](./05-出海ERP-没库存时自产自销还是转口贸易.md)）。  
- **产品与客户资质**：部分外销品有认证或客户准入，可在主数据加 **允许销售区域** 或评审时校验（与 [合同评审](./07-出海ERP-合同评审单从接单到排产.md) 衔接）。

销售最讨厌「多填表」。妥协办法：**80% 字段由订单类型默认带出**，销售只改数量、交期、收货地址；IT 在蓝图阶段把默认项配好，而不是上线后每个单手工选税。

### 报表：老板要的「内销/外销」要和录单一致

常见管理报表：

- 按 **法人** 收入（合并前）。  
- 按 **内/外销** 或 **国家/区域**（分析维度来自 SO 类型，不是事后 Excel 标）。  
- 按 **产品/BU**（与是否外销无关，但外销品有时 SKU 不同）。

若 SO 创建时没选 **销售类型**，月底财务用备注列「这单算出口」——那就是 **主数据与订单类型设计失败**，不是财务不认真。

### 和一期边界的关系

M1 专题 [【分期表】](./03-分期表-制造贸易ERP一张表划清一期和二期.md) 里「跨境多法人」常放二期，但 **海外工厂主体** 往往 **第一天就有外销**。一期至少做到：

- 内/外销 **订单类型可分**；  
- 税与发票 **意图可分**（哪怕先只做一种发票全功能，另一种走例外流程并留痕）；  
- 客户主数据 **开票方/收货方/集团关联** 有字段或备注规范。

不必一期做全球合并，但 **不能把内外销糊成一种 SO**，等二期再拆——历史订单清洗会比当初省下的配置时间贵得多。

### 自检三问（立项工作坊 15 分钟）

1. 新销售入职：**创建一张外销 SO 要点几下、默认带出什么？**  
2. 财务月结：**内/外销收入各从哪张报表出、能否对到 SO 列表？**  
3. 直发第三国：**客户、收货方、内部采购方在系统里各是谁？**

答不清，先别加模块，先改 **订单类型与客户主数据**。

### 主数据与订单字段（Odoo 等系统的常见映射）

不写实施细节，只列 **方案必对齐的字段逻辑**（年费套件有等价配置页）：

| 业务含义 | 典型字段/配置 | 内外销差异 |
|----------|---------------|------------|
| 合同客户 | 客户（Partner） | 同一 Partner 可有不同 **价格表** |
| 开票对象 | 开票地址 / `invoice` 联系人 | 集团采购、工厂开票给甲 |
| 收货对象 | 送货地址 / `delivery` 联系人 | 直发丙国终端 |
| 税务 | 财政立场（Fiscal Position） | 内销含 VAT 映射；外销出口映射 |
| 价格 | 价格表 + 贸易条款 | 外销常不含运费或含 DDP 包干价 |
| 分析维度 | 分析账户 / 销售团队 / 国家 | 报表按 **订单类型** 带出，不靠备注 |

上线验收抽一单：**截图 SO 上客户、开票、收货、税、订单类型五处**——与 [评审单](./07-出海ERP-合同评审单从接单到排产.md) 和 [出库检查](./06-出海ERP-销售出库前系统必须回答的三个问题.md) 能 **逐字段对应**。
