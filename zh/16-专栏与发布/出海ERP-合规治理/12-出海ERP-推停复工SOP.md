**标题：【出海 ERP】「推一下、停一下」：海外 ERP 长停顿的同一模式与复工 SOP**

海外制造主体、订单量不算爆炸的 ERP 项目，我也见过 **停两次、每次几周到几月**。表面理由各不相同：财务口径、进口费用、集团调度邮件——拆到底，经常是 **同一模式**：

> **外部确认没闭合** → 项目组 **怕耽误工期** → **并行配 Odoo / 烧人天** → 周报全是「配置率」→ **财务仍不签字** → 管理层觉得「在推进」、CFO 觉得「没进度」→ **整段静默或撕 SOW**。

这不是某一家公司的专利，是 **缺基线仍开工** 的通用翻车。  
[B5「对齐会三件套」](./05-出海ERP-先总后分90分钟专项对齐会.md) 解决 **怎么产出三件套唯一基准**（本篇 **不重写** 90 分钟议程）；[B2「双轨进度表」](./02-出海ERP-财务未签字进度作废双轨进度表.md) 解决 **怎么把真假进度分开**。这篇补 **叙事 + 复工 SOP**：**停顿后先更基线，再开 3.x 实施商交付。**

### 同一模式（四段 · 对照表）

| 阶段 | 现场白描（脱敏） | 进度表上常发生什么 |
|------|------------------|-------------------|
| **① 推** | 微信群里「先把销售/仓库跑通」；财务说「先看流程」 | 开发轨行数猛涨；合规轨 **2.1～2.3 全空** |
| **② 假进度** | 演示菜单、截图、UAT 条数堆满 | **可验收进度** 仍 0（B2 规则） |
| **③ 停** | 邮件变少、例会取消、乙方待命 | 人天消耗已发生，**无签字 artifact** |
| **④ 再推** | 管理层加日期/加人天 | 若 **不先更基线** → 回到 ① |

**数字化负责人** 深度介入，往往发生在 **③→④** 之间（[B8「三触发四问」](./08-出海ERP-数字化负责人三触发四问.md)）。**更便宜的动作** 是在 **① 之前** 锁 [B1「合规 DoD」](./01-出海ERP-上线成功不是GoLive是合规账务与法定报表.md) 与 2.3 计划日。

### 流程链：推 → 停 → 复工（ASCII）

```
[外部确认未闭合] ──并行──> 3.x 配置/开发 ──> 配置率↑ 可验收=0
        │                                      │
        └──────────────> 停顿 ──────────────────┘
                              │
                    复工 SOP（本篇核心）
                              │
        ① 冻结 3.x 新 scope（变更单除外）
        ② 更新场景表 v1 + 三件套同版（材料见 B5）
        ③ 重填 B2 双轨表（2.3 四字段见 B7）
        ④ 2.3 实际确认日 或 书面计划 再开 3.x
        ⑤ 周报只报 合规闭合率 + 可验收进度
```

### 复工 SOP（项目负责人 · 逐步）

| 步 | 动作 | 交付物 | 通过标准 |
|----|------|--------|----------|
| **R1** | **宣布冻结** | 邮件/群公告：无签字基线不扩配置 | 乙方 **书面** 确认暂停依赖口径项 |
| **R2** | **更场景表** | 场景表 v1 + **二期非目标** | 财务 **48h 内** 书面反馈或参会 |
| **R3** | **更三件套** | 场景表 / 流程基准 / 分录规则 **同版本号** | 数字化负责人 **A** 方向（B5） |
| **R4** | **更双轨表** | 合规轨 2.1～2.3 行 + 开发轨 **可验收=否** 直到 2.3 开 | 2.3 **计划确认日** 必填 |
| **R5** | **开总闸门** | 2.3 **实际确认日** 或 分步 2.1/2.2 签字 | 空则 **Go-Live 标高风险**（B7） |
| **R6** | **恢复 3.x** | 按 [B6「WBS 五层」](./06-出海ERP-WBS第一层只留五顶.md) 父项挂行 | 每行绑 **演示或文档 diff** |
| **R7** | **汇报** | 任务编号 + 完成度 + 下一里程碑（见 **B11**） | 不用「整体 %」替代合规 |

**硬门禁**：**R5 未过** → **禁止** 用「复工」名义重启 **依赖分录/报表口径** 的配置（[B9「三方 RACI」](./09-出海ERP-三方RACI一页纸.md)：财务定规则，实施商配系统）。

### UAT 等价 · 复工签字标准（可测试）

停顿后复工，**第一次 UAT** 不应从「点菜单」开始，而从 **财务路径** 开始：

| 抽单 | 路径 | 通过标准 |
|------|------|----------|
| **U-R1** | 一张 **已锁场景** 的销售出库（或评审→生产→入库） | 凭证 **科目/税** 与分录规则 v1 **一致** |
| **U-R2** | 一张 **进口/贸易** 费用进成本或费用 | 附件 **货代账单** 与 PO 三单匹配 |
| **U-R3** | **法定报表** 试算（月结或表样） | 财务 **书面**「可出表/需调整清单」 |

**签字**：F **A** · V **R** 交付说明 · PM **R** 归档 · 未过 **不得** 报「复工完成」。

### 一期最少 3 条 · 二期可延后 1 条

| 期别 | 内容 |
|------|------|
| **一期必做** | ① 复工 SOP R1～R5 ② 双轨表合规轨更新 ③ U-R1～U-R3 至少过 2 项 |
| **二期可延后** | 全模块回归、报表美化 |

### 反例（2 条）

- **停顿后直接加人天**，场景表仍 v0 → 第二次停得更久。  
- **复工会开了 3 小时**，双轨表 **未改** → 仍是假进度。
