**标题：【出海 ERP】上线成功不是 Go-Live，是合规账务 + 法定报表**

> 延伸阅读「出海 ERP · 合规治理」第 1 篇 · 2026-10-30 定稿  
> 业务操作篇见主专栏 [出海 ERP 05～16](./../README.md#延伸阅读出海-erp2026-10)  
> 本系列索引 [合规治理](./README.md)  
> 下篇：[续读](./02-出海ERP-财务未签字进度作废双轨进度表.md)

某次海外 ERP 复盘里，信息总监和项目负责人吵的不是「菜单少了一个」，而是 **什么叫上线成功**。开发侧报：销售能录单、仓库能出入库、财务能过账。CFO 问：**法定报表谁认？外审要的附注谁签？** 会议室安静了——因为合同里写的往往是「系统上线」，没人把 **合规账务 + 法定报表** 写成 DoD（Definition of Done）。

我在 **中东/东南亚制造主体**（自产+贸易、多法人、本地 VAT）类项目里见过太多次：**Go-Live 庆功了，月结关不了账，法定报表出不来**，二期再补场景——那不是二期，是 **一期范围偷换**。

### 先把话说死：ERP 在本项目的「基本功能」是什么

| 常见误解 | 更接近财务/外审的表述 |
|----------|------------------------|
| 流程都配好了 | **分录规则定稿**：什么业务事件生成什么科目、谁批 |
| 用户能登录操作 | **场景定稿**：哪些单据类型、哪些法人、哪些贸易路径在一期 |
| UAT 打勾 200 条 | **报表路径闭合**：试算平衡 → 管理报表 → **法定报表** 有样张 |
| 乙方人天用完了 | **签字闭合**：财务（及必要时的外审/代理）**书面确认**口径 |

**DoD 一句话（建议写进 SOW 首页）**  
在 **已锁定的业务场景表** 范围内，系统产生的账务能支撑 **合规账务** 与 **当地法定报表**（清单见附件），并由 **财务负责人（及外审/代理，若适用）** 在 **约定日期前** 签字确认。

「模块能用」是 **必要条件**，不是 **充分条件**。

### 一页纸「合规账务与法定报表说明」（模板）

复制到项目 Confluence/飞书，**空白处填完再开工大范围配置**：

| 区块 | 填什么 | 谁签字 | 截止日期 |
|------|--------|--------|----------|
| **A. 场景范围** | 销售/采购/库存/生产（一期含哪些、二期不含哪些）；法人主体清单；贸易路径（内销/外销/进口） | 业务负责人 + 财务 | |
| **B. 法定报表清单** | 利润表、资产负债表、VAT 申报表、（若适用）工资/GOSI 相关附表……**列全称** | 财务 + 外审/代理（若有） | |
| **C. 凭证与分录** | 关键业务（销售发货、采购入库、生产完工、进口费用、汇兑）→ **分录样例** 或规则表编号 | 财务 | |
| **D. 验收签字方** | 财务确认人、外审对接人、乙方交付负责人、内部 IT/项目负责人 | 四方知悉 | |
| **E. 非目标（二期）** | 制造 MRP 全量、合并报表、集团调度……**写清「本期不做」** | 信息总监/数字化负责人 | |

**规则**：B、C 未签字前，进度表上的「开发完成率」**不计入可验收进度**（与 B2 双轨表联动）。

### 一期最少 3 条 + 二期明确延后 1 条（示例）

| 类型 | 内容 | 说明 |
|------|------|------|
| **一期必做 ①** | 进销存 + 基础财务 + **本地 VAT 销售路径** 可关账 | 与 [A1 决策树](./../05-出海ERP-没库存时自产自销还是转口贸易.md)一致 |
| **一期必做 ②** | 进口采购 + 货代费用 **挂账规则** 定稿（不必一次做满全部贸易条款） | 见 [A8 费用节点](./../12-出海ERP-货代服务付款节点清单.md) |
| **一期必做 ③** | **三张样张**：试算平衡、管理利润表、**一张法定报表**（如 VAT 申报底稿） | UAT 抽单来源 |
| **二期延后** | 全制造 APS、集团合并、多公司自动调度 | 写进 SOW「非 DoD」 |

### 从场景到报表：一条 ASCII 链（蓝图附件用）

```text
业务场景表（签字）
    → 主数据 + 单据类型（SO/PO/MO/入库/发票）
    → 自动化分录 / 凭证模板（财务签字）
    → 试算平衡（期间关闭演练）
    → 管理报表（工厂/法人）
    → 法定报表（财务 + 外审样张）
    → DoD 达成（书面确认）
```

任何一环只有「演示 PPT」没有 **财务签字件**，都不算 DoD 闭合。

### UAT 抽单表（可测试的通过标准 · 节选）

| # | 场景 | 输入单据 | 通过标准（财务可验） |
|---|------|----------|----------------------|
| 1 | 本地销售含 VAT | SO→发货→发票 | VAT 行与税额与合同模板一致；分录科目=规则表 # |
| 2 | 进口 PO 到货 | PO→收货→供应商账单 | 关税/运费进库存或费用科目=规则表 # |
| 3 | 生产完工（若一期含 MO） | MO→完工入库→成本结转 | 库存金额与 BOM 假设一致；无「只入库不过账」 |
| 4 | 期间关闭 | 月结 checklist | 试算平衡；**无法过账的草稿单=0** |
| 5 | 法定报表 | 导出/打印 | 与 Excel 手工底稿 **差异在约定阈值内**（如 0 或仅 rounding） |

UAT **条数多** 但 **法定路径未测** = 假进度（B 组续篇会写）。

### 两个反例（别踩）

1. **「先上线再对口径」**：配置改三轮，财务仍无签字基线——停顿会叠停顿。  
2. **「乙方说标准模块就够用」**：海外 VAT、进口费用、多法人维度 **不在标品默认 DoD 里**，必须写进 **C. 凭证与分录**。

### 和信息总监、项目负责人、财务的分工（一句话）

- **财务**：定规则、认报表、**签字**；不替乙方配 Odoo。  
- **项目负责人**：收齐 A～E 页、约确认会、**无签字则升级阻塞**（不能甩锅「财务忙」）。  
- **信息总监/数字化负责人**：审 DoD 方向；**无书面 DoD 不放权大范围开发**。
